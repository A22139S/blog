## 媒体查询的局限

传统响应式设计依赖媒体查询，但媒体查询只知道**视口大小**，不知道组件所处的**容器大小**。

这导致一个经典困境：同一个卡片组件，在侧边栏里宽度只有 300px，在主区域里宽度有 800px——但它无法"感知"自己在哪里。

## 容器查询的解法

```css
/* 第一步：将父容器声明为查询容器 */
.card-wrapper {
  container-type: inline-size;
  container-name: card; /* 可选：命名容器 */
}

/* 第二步：在子组件中响应容器宽度 */
.card {
  display: flex;
  flex-direction: column; /* 窄容器：纵向排列 */
}

@container card (min-width: 400px) {
  .card {
    flex-direction: row; /* 宽容器：横向排列 */
  }
}
```

## 与媒体查询的对比

| 特性 | 媒体查询 | 容器查询 |
|------|---------|---------|
| 响应目标 | 视口（viewport） | 父容器 |
| 组件复用性 | 差（与布局耦合） | 优（与布局解耦） |
| 设计系统友好度 | 一般 | 非常友好 |
| 浏览器支持 | 全覆盖 | Chrome 105+ / Safari 16+ / Firefox 110+ |

## 实战：自适应文章卡片

```css
.posts-grid {
  container-type: inline-size;
}

.post-card {
  padding: 1rem;
}

/* 窄布局（< 480px）：紧凑单列 */
.post-card__image { display: none; }
.post-card__title { font-size: 1rem; }

/* 中等布局（480px ~ 720px）：显示封面图 */
@container (min-width: 480px) {
  .post-card { display: grid; grid-template-columns: 120px 1fr; gap: 1rem; }
  .post-card__image { display: block; }
  .post-card__title { font-size: 1.125rem; }
}

/* 宽布局（≥ 720px）：大图展示 */
@container (min-width: 720px) {
  .post-card { grid-template-columns: 200px 1fr; }
  .post-card__title { font-size: 1.5rem; }
  .post-card__excerpt { display: block; }
}
```

## 结合 CSS Grid 实现真正自适应布局

```css
/* 自动填充列，每列最小 300px */
.auto-grid {
  container-type: inline-size;
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(min(300px, 100%), 1fr));
  gap: 1.5rem;
}
```

容器查询让我们终于可以构建**真正可移植的 UI 组件**——把它放在任何地方，它都能优雅地适应自己的空间。这才是组件化设计应有的样子。
