Next.js 14 App Router 完全指南：从零到生产

2024年3月15日 · 博客作者 · 约 6 分钟阅读 · 4 个章节
深入探讨 Next.js 14 的 App Router 架构，涵盖服务端组件、流式渲染、数据获取模式等核心概念，帮助你构建现代化全栈应用。

什么是 App Router？

Next.js 13 引入、14 正式稳定的 App Router 是对原 Pages Router 的彻底革新。它基于 React Server Components（RSC）构建，带来了更好的性能和开发体验。

App Router 最核心的理念是：服务器优先。减少发往客户端的 JavaScript 体积，让用户获得更快的首屏加载速度。

核心概念对比

特性Pages RouterApp Router
默认组件类型客户端组件服务端组件
数据获取getServerSideProps直接 async/await
布局嵌套_app.tsx 单层多层嵌套 layout.tsx
流式渲染不支持原生支持 ✅

服务端组件 vs 客户端组件

App Router 最大的变化是默认所有组件都是服务端组件。服务端组件可以直接访问数据库、文件系统和私密 API，零客户端 JavaScript 开销。

服务端组件示例

// 服务端组件：直接 await，无样板代码
export default async function PostsPage() {
  const posts = await db.post.findMany({
    orderBy: { date: 'desc' }
  })
  return (
    <ul>
      {posts.map(post => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  )
}

需要交互的组件才加上 'use client' 指令，如表单、按钮点击处理、浏览器 API 调用等场景。

数据获取模式

App Router 彻底简化了数据获取。在服务端组件中，你可以直接使用 async/await 加载数据，不再需要 getServerSideProps 或 getStaticProps。

并行请求

使用 Promise.all 并行发起多个请求，避免瀑布式串行等待，显著提升性能：

export default async function DashboardPage() {
  // 并行请求，而非串行等待
  const [user, posts, analytics] = await Promise.all([
    fetchUser(),
    fetchPosts(),
    fetchAnalytics(),
  ])
  return <Dashboard user={user} posts={posts} analytics={analytics} />
}
